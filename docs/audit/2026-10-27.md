# Skyriders audit fixes and traversal validation

## Scope and result

Skyriders was pulled with `git pull --ff-only` before the audit. The clean baseline was `fd2863d` on `1.20.1/main`; changes are on `fix/audit-and-traversal`.

The 21 audit findings below have code fixes. Final validation passes 67 Skyriders tests, including 48 simulations using the rebuilt native physics engine, and 11 required Forge GameTests. The Minecraft traversal test contains 12 independent vehicle/course lanes. These results establish the tested cases, not correctness for every vehicle configuration, terrain shape, mod combination or multiplayer session.

## Block and slope traversal

The old wheel ray fans did not represent wheel volume or chassis clearance. A ray could find lower ground after entering an obstacle, and independent wheel impulses did not plan the body's ascent over repeated risers. Treating nominal model ride height as centre-of-mass height also delayed assistance for the motorcycle.

The current native voxel shape has a stub PhysX sweep implementation, so calling that sweep alone would silently miss Minecraft terrain. The native patch implements box/sphere queries over actual voxel sub-boxes and supported primitives, independently of the active solver. It returns overlap status, body/segment identity, contact geometry and surface linear/angular motion. Unsupported shapes conservatively block the query. Query-relative coordinates avoid loss of precision at large world coordinates.

All three vehicle solvers now use sphere wheel support and one traversal controller. The controller detects a reachable step relative to the supporting slope, checks upward/forward chassis clearance, samples the upcoming terrain, and applies a bounded, timed force transition. It uses actual compound shapes, pivot offsets and scaling for chassis clearance. Moving supports receive opposite forces/torques. Brakes, engine shutdown and unsupported geometry disable assistance; a vehicle already in free flight cannot acquire a new step plan.

`stepAssistStrength` now caps the vehicle's added upward force in newtons. Built-in enabled configurations use `mass * 45`; the controller also retains that acceleration ceiling. Zero disables assistance. Force-budget tests cover zero and a smaller custom limit.

Native scenarios cover:

- Motorcycle, kart, ATV, car and pickup over a full block at 4, 12 and 24 m/s.
- Car half blocks, repeated half-block stairs, 30-degree ramps and raised ramp crests; other vehicle types on stairs/raised crests at 24 m/s.
- Reverse at 4/12/24 m/s; translating and yawing supports; airborne, tall-wall, ceiling, engine-off and braking cases.
- Compound pickup geometry, actual centre-of-mass pivots, force-position conventions and a longer slow-speed landing run.

Assertions cover progress, retained speed, finite state, bounded launch height and sampled chassis penetration. Corner sampling is not a proof that every possible intersection is absent. High-speed crest flight is bounded using the available vertical kinetic energy rather than incorrectly requiring continuous ground contact. The tested vehicles use their default scale; suspension wheel dimensions are not currently adjusted for arbitrary body scaling.

The Forge course uses actual stone/slab voxels: five vehicle types on full blocks and repeated slab steps at 24 m/s, plus car full-block approaches at 4 and 12 m/s. A repeat-run failure was traced to flowing water entering the generated underground course, not step assistance; the test now seals its volume and asserts the path is dry. Normal drag/lift/buoyancy settings were restored for final validation.

## Building and testing Skyriders

Gradle resolves the published versions pinned in [gradle.properties](../../gradle.properties). Maven local is excluded from Skyriders' project repositories. The former local-stack bootstrap scripts were removed; dependency releases belong to their upstream repositories.

With Java 17, run `./gradlew build exportServerRuntime runAuditServer -PgameTests --no-daemon --max-workers=4` (`gradlew.bat` on Windows) to run unit/native tests and the Forge GameTests and export the matching production runtime mods.

The audit client can be launched manually with `./gradlew.bat runAuditClient`; it uses `run-audit-client`. The automated server uses `run-audit`. Both are separate from the existing `run` directory.
